# Deployment — Vercel + Render + Neon

This is how the [live demo](https://moneywealth-chi.vercel.app) runs, entirely on
free tiers:

```
Browser ──► Vercel (Next.js 16 + BFF)  ──►  Render (FastAPI, Docker)  ──►  Neon (Postgres 18)
                                                     │
                                                     └──►  Render Key Value (Redis)
```

| Piece | Where | Config |
|---|---|---|
| Frontend + BFF | Vercel | `frontend/vercel.json` |
| Backend API + sync worker | Render web service (Docker) | [`render.yaml`](../render.yaml) Blueprint |
| Redis (rate limits, AI token budgets) | Render Key Value | `render.yaml` |
| PostgreSQL | Neon | migrations in `backend/db/migrations/` |

> **Why Neon and not Render Postgres?** The cross-tenant `SECURITY DEFINER`
> functions (sync-job queue, Plaid webhook routing, admin console) run as the
> table owner on `FORCE ROW LEVEL SECURITY` tables, so the owner role needs
> `BYPASSRLS`. Managed Postgres without a superuser (Render) can't grant it;
> Neon's `neondb_owner` already has it. RDS works too — see [deploy-aws.md](deploy-aws.md).

## 1. Database — Neon

1. Create a project at <https://neon.tech>. Pick a region and put the Render
   services in the **same** one (`us-east-2` ↔ Render `ohio`).
2. Copy the **direct** connection string (connection pooling **off** — asyncpg
   uses prepared statements, which transaction-mode poolers break). Drop the
   `channel_binding=require` parameter; keep `sslmode=require`.
3. Create the **non-owner app role** first, with a strong password (Neon rejects
   weak ones; migration `003` only creates `app_user` if it doesn't exist):
   ```sql
   CREATE ROLE app_user LOGIN NOBYPASSRLS PASSWORD '<long random password>';
   ```
4. Run migrations as the owner, from `backend/`:
   ```bash
   MIGRATION_DATABASE_URL="postgresql://neondb_owner:...@<host>/neondb?sslmode=require" \
     python -m scripts.migrate
   ```
5. The app's `DATABASE_URL` is the same host with the `app_user` credentials.

## 2. Backend — Render Blueprint

1. Render dashboard → **New → Blueprint** → select this repo. Render reads
   [`render.yaml`](../render.yaml) and creates `moneywealth-api` (Docker, free)
   and `moneywealth-redis` (Key Value, free, internal-only).
2. Fill the prompted secrets: `DATABASE_URL` (app_user DSN), `WEB_APP_URL`
   (the Vercel URL), `GROQ_API_KEY`, `PLAID_CLIENT_ID`, `PLAID_SECRET`,
   `PLAID_ENC_KEY`. Generate the encryption key with:
   ```bash
   python -c "import os,base64;print(base64.b64encode(os.urandom(32)).decode())"
   ```
   JWT secrets are generated by Render; `REDIS_URL` is wired from the Key Value
   service.
3. Deploy, then check `https://<service>.onrender.com/health/ready` →
   `{"status":"ready","checks":{"db":"ok","redis":"ok"}}`.

Notes:
- `ENV=production` refuses a wildcard Host allowlist. The Dockerfile defaults
  `ALLOWED_HOSTS` to Render's `RENDER_EXTERNAL_HOSTNAME`, so no extra config.
- Pushes to `main` that touch `backend/**` auto-deploy. Schema changes are
  **not** applied by the service (it only holds the app role) — run step 1.4
  before deploying code that needs a new migration.
- The free instance sleeps after 15 minutes idle; the first request after that
  takes ~1 minute. The Starter plan keeps it warm.

## 3. Frontend — Vercel

```bash
cd frontend
vercel link                     # or import the repo in the dashboard, root = frontend/
vercel env add API_BASE_URL production         # https://<service>.onrender.com (server-only)
vercel env add NEXT_PUBLIC_APP_URL production  # https://<project>.vercel.app
vercel deploy --prod
```

`frontend/vercel.json` pins the **Next.js** framework preset — a project created
from the CLI otherwise defaults to "Other" and serves only `public/` (every route
404s). For deploy-on-push, either connect the repo in Vercel or add a
`VERCEL_TOKEN` repo secret for [`deploy-frontend.yml`](../.github/workflows/deploy-frontend.yml).

## 4. Smoke test

- Open the Vercel URL → sign up → log in.
- Verify the email (see [email-setup.md](email-setup.md); with
  `MAIL_TRANSPORT=console` the link is only in the backend log).
- Link a Plaid **sandbox** bank (`user_good` / `pass_good`) → transactions,
  debt and portfolio populate within seconds.
- Ask the advisor *"What are my account balances?"* — the reply should cite the
  `get_account_balances` tool.
